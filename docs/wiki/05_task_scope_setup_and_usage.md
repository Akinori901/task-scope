# Task Scope — ローカル設定・操作ガイド

## Task Scope とは

Task Scope は、本案件で使用している **Backlog のチケットを横断的に分析するツール** です。
複数スペースのチケットを一元的に収集し、進捗・難易度・工数を可視化するダッシュボードを提供します。

主な特徴:

- Backlog の複数スペースを横断してチケットを集約
- ダッシュボードでステータス分布・担当者負荷・遅延チケットを可視化
- AI によるチケットの難易度評価・工数見積・方針書の自動生成
- ガントチャートによるマイルストーン単位のスケジュール管理

## 初回セットアップ

### 1. リポジトリのクローン

```bash
git clone <リポジトリURL>
cd task-scope
```

### 2. 環境変数の設定

```bash
cp .env.example .env
```

`.env` を開き、以下の値を確認・設定します:

```env
# Django
SECRET_KEY=your-secret-key-change-this-in-production
DEBUG=True
ALLOWED_HOSTS=localhost,127.0.0.1

# MySQL
MYSQL_ROOT_PASSWORD=secret
MYSQL_DATABASE=task_scope
MYSQL_USER=user
MYSQL_PASSWORD=secret

# AI 評価プロキシ（AI 機能を使う場合）
EVAL_PROXY_URL=http://host.docker.internal:19001
EVAL_PROXY_PORT=19001

# ポート番号（他のサービスと被る場合のみ変更）
BACKEND_PORT=19000
FRONTEND_PORT=3100
DB_PORT=13307
PHPMYADMIN_PORT=19080
```

> ポート番号は他プロジェクトのサービスと衝突しないよう設定されています。
> 競合がなければデフォルトのまま使用してください。

### 3. セットアップ実行

```bash
make setup
```

以下が自動で実行されます:
1. Docker イメージのビルド
2. コンテナの起動
3. データベースのマイグレーション

完了すると以下の URL にアクセスできます:

| サービス | URL |
|---------|-----|
| Task Scope（メイン画面） | http://localhost:3100 |
| バックエンド API | http://localhost:19000/api/ |
| phpMyAdmin | http://localhost:19080 |

## スペースの登録（初回のみ）

Task Scope を使うには、まず分析対象の Backlog スペースを登録する必要があります。

### Backlog スペースの登録

1. http://localhost:3100/settings を開く
2. 「接続設定」タブの「Backlog スペース」セクションで「追加」をクリック
3. 以下の情報を入力:

| 項目 | 入力内容 | 例 |
|------|---------|-----|
| スペースキー | Backlog のスペース識別子 | `example-biz` |
| ドメイン | `backlog.jp` または `backlog.com` | `backlog.com` |
| API キー | Backlog の個人設定 → API で発行 | `LCiN4Oyj...` |

※ APIキーの取得は [Backlog API 連携セットアップ手順] 参照

4. 保存後、「同期」ボタンをクリック

> **API キーの発行方法**: Backlog にログイン → 右上のアイコン → 個人設定 → API → 「新しいAPIキーを発行」

## 自分のユーザー紐づけ

「自分向け」フィルタでチケットを絞り込むために、各スペースで自分のユーザーを紐づけます。

1. 設定画面 →「接続設定」タブ →「自分の紐づけ設定」
2. 各スペースの自分のユーザーを選択して「自分」ボタンをクリック

紐づけ後、画面右上の「全体 / 自分」切替で自分に関連するチケットのみ表示できます。

## 画面の使い方

### ダッシュボード（トップページ）

http://localhost:3100

全スペースのチケットを横断した統計を表示します。

| セクション | 内容 |
|-----------|------|
| 統計カード | 総チケット数・未対応・完了・遅延などの件数 |
| ステータス分布 | チケットのステータスごとの件数をグラフ表示 |
| 担当者負荷 | 担当者ごとの総チケット数・遅延数 |
| 要注意チケット | 遅延・停滞しているチケットの一覧 |
| ピン留めチケット | 自分が注目しているチケットへのショートカット |

**フィルタ**: プロジェクト・ステータス・担当者・カテゴリ・マイルストーン・検索で絞り込み可能

**表示切替**: 画面右上の「全体 / 自分」ボタンで全チケット表示と自分のチケット表示を切り替え

### チケット一覧

http://localhost:3100/tickets

全チケットをテーブル形式で表示します。

| 機能 | 操作 |
|------|------|
| ソート | 列ヘッダーをクリック（キー・件名・ステータス・優先度・期限） |
| フィルタ | 画面上部のフィルタで条件指定 |
| 完了除外 | 「完了を除外」チェックボックスで完了チケットを非表示 |
| CSV 出力 | 「CSV」ボタンで一覧をダウンロード |
| 親子展開 | 子チケットがあるチケットの ▼ をクリックで子を展開表示 |

行をクリックするとチケット詳細に遷移します。

### チケット詳細

http://localhost:3100/tickets/:id

個別チケットの詳細情報と AI 分析結果を表示します。

**基本情報**: ステータス・優先度・担当者・期限・親子関係など

**AI 評価（eval-proxy 起動が必要）**:

| ボタン | 機能 |
|--------|------|
| 再採点 / 採点 | 6軸の難易度評価 + 推定工数 + チケット品質判定を AI が実行 |
| 方針書生成 | チケット情報とコードベースから実装方針書を AI が自動生成 |

AI 評価で出力される情報:

- **難易度レーダーチャート**: 影響範囲・クエリ複雑度・曖昧度・検証難度・調整コスト・リグレッションリスクの6軸
- **対処区分**: データ修正 / コード修正 / 設定変更 / 調査のみ / 複合
- **推定工数**: フェーズ別（分析・実装・レビュー・テスト・デプロイ）の人日見積
- **情報品質**: 方針書を書けるだけの情報が揃っているかの判定

**コメント**:

| 操作 | 説明 |
|------|------|
| コメント追加 | 「コメント追加」ボタンで新規作成 |
| タグ付け | spec（方針書）/ PR / report（報告書）/ decision（決定事項）/ blocker |
| Backlog に投稿 | 「投稿」ボタンで外部サービスにコメントを送信 |
| 絞り込み | タグでコメントをフィルタ表示 |

**ピン留め**: 「ピン留め」ボタンでダッシュボードのピン留めチケットに追加

### ガントチャート

http://localhost:3100/gantt

マイルストーン単位でチケットの進捗をタイムライン表示します。

| 機能 | 操作 |
|------|------|
| プロジェクト絞り込み | プルダウンで特定プロジェクトのみ表示 |
| カテゴリ絞り込み | プルダウンでカテゴリ指定 |
| マイルストーン選択 | チェックボックスで表示するマイルストーンを選択 |
| 表示開始日 | 日付入力でタイムラインの表示範囲を指定 |
| Excel 出力 | 「Excel出力」ボタンでガントチャートをダウンロード |
| マイルストーン展開 | マイルストーン行をクリックで所属チケットを展開 |
| 完了除外 | 「完了を除外」チェックで完了チケットを非表示 |

マイルストーンのバーは、所属チケットの進捗状況に応じて色分け表示されます:

| 色 | 意味 |
|----|------|
| 緑 | 完了 |
| 青 | 進行中 |
| オレンジ | 未着手 |
| グレー | 停滞 |

## 設定画面の詳細

http://localhost:3100/settings

### 接続設定タブ

- **Backlog スペース**: 登録・編集・削除・同期
- **Jira スペース**: 登録・編集・削除・同期
- **自分の紐づけ設定**: 各スペースで自分のユーザーを選択
- **除外ステータス設定**: プロジェクトごとに「完了扱い」にするステータスを指定（例:「対応不要」「保留」など）

### プロジェクト設定タブ

- **コードリポジトリ**: プロジェクトとローカルのコードリポジトリを紐づけ
  - AI 方針書生成時にコードベースを参照するために使用
  - 「パス選択」ボタンでディレクトリをブラウズ可能
  - 複数リポジトリの紐づけ可能（例: フロント + API）

### マイルストーンタブ

- マイルストーンの一覧表示・期間編集
- ガントチャートの表示に使用される

### バッファ設定タブ

- AI 工数見積の係数調整
- フェーズ別（分析・実装・レビュー・テスト・デプロイ）のバッファ倍率
- 不確実性に応じた最小・最大係数

### 表示設定タブ

- デフォルトのコメントタグフィルタ（チケット詳細を開いた際の初期表示タグ）
- カラーモード（ライト / ダーク）

## AI 評価機能の使い方

AI 評価機能を使うには、ホストマシン上で eval-proxy を起動する必要があります。

### 前提条件

- Claude Code CLI がホストマシンにインストールされていること

### 起動

```bash
# make up に含まれるため、通常は自動で起動します
# 手動で起動する場合:
make eval-proxy-bg

# 動作確認
make eval-proxy-status
```

### 使い方

1. チケット詳細画面を開く
2. 「採点」ボタンをクリック → AI が難易度・工数・品質を評価（数十秒かかります）
3. 評価結果が画面に表示される
4. 情報品質が「情報十分」と判定された場合、「方針書生成」が利用可能
5. 生成された方針書は `docs/policies/` にも保存される

### 方針書の投稿

1. 方針書が生成されるとコメント欄に spec タグ付きで表示される
2. 「投稿」ボタンで Backlog にコメントとして投稿可能
3. チケット一覧画面の「未投稿方針書」ボタンで未投稿の方針書を一括投稿可能

## 日常の操作

### 起動

```bash
make up
```

ブラウザで http://localhost:3100 を開きます。

### データ同期

チケットデータを最新にするには:

- **画面から**: 画面右上の「同期」ボタンをクリック
- **コマンドから**: `make sync-backlog`
- **設定画面から**: 各スペースの「同期」ボタンをクリック

> 同期は全チケットのステータス・コメント・担当者などを最新の状態に更新します。
> 初回同期はチケット数に応じて数分かかる場合があります。

### 停止

```bash
make down
```

## トラブルシューティング

| 症状 | 原因 | 対処 |
|------|------|------|
| 画面が表示されない | コンテナ未起動 | `make up` で起動 |
| チケットが 0 件 | スペース未登録 or 未同期 | 設定画面でスペースを登録し同期を実行 |
| 「自分向け」が 0 件 | ユーザー紐づけ未設定 | 設定画面で自分のユーザーを選択 |
| AI 評価が動かない | eval-proxy 未起動 | `make eval-proxy-bg` で起動、`make eval-proxy-status` で確認 |
| AI 評価がタイムアウト | 処理に時間がかかっている | 再度実行。コードリポジトリが大きい場合は時間がかかることがある |
| 同期で 0 件 | API キー無効 or スペースキー誤り | 設定画面で接続情報を確認 |
| DB 接続エラー | MySQL コンテナ未起動 | `make ps` で確認、`make restart` で再起動 |
| ポートが使えない | 他のサービスと衝突 | `.env` でポート番号を変更 |
